# UO · Ветви сценария

Архитектура кампании: узлы, развилки, метки и финалы. Ведущий пишет, что на что
выводит, отмечает случившееся — и видит, какие финалы ещё в игре, а какие партия
уже отрезала.

Foundry **v13–v14**. Сторонних модулей не требует. Граф видят только ведущие.

## Сценарий — это журнал

Сценарий не живёт внутри модуля: сценарий — обычный журнал, узел — его страница.
Текст пишется штатным редактором, ссылки на сцены и актёров работают сами, права
раздаются как всегда, а готовый сценарий кладётся в компендиум и уезжает другому
ведущему целиком — вместе с прозой. Модуль добавляет к журналу только связи:
стрелки, метки и ход кампании лежат в его флагах. Уберёте модуль — останется
журнал со страницами, а не мусор.

Войти можно кнопкой **«Ветви»** в шапке боковой панели журналов или правой
кнопкой по журналу — «Ветви: сделать сценарием». Уже написанный журнал
превращается в граф: узлы разложатся сами, останется протянуть стрелки.

## Схема может приезжать из markdown

Стрелки живут во флагах журнала, а сборка компендиума сносит пакет целиком
и собирает заново. Значит протянутое руками в компендиуме не переживёт первой
же пересборки, а копия, импортированная в мир, перестанет получать правки.

Поэтому схему можно объявить прямо в исходнике карточки — блоком `vetvi`
в шапке: узлы (какая страница чем является и где стоит на холсте), стрелки
с условиями и список меток. Сборка раскладывает это по флагам сама, считая
id страниц тем же хешем, каким создаёт страницы, — ссылаться можно **именами**.

Так схема едет вместе с текстом, а правится там же, где пишется сценарий.

**Перетаскивание создаёт копию, а не обновляет.** Поэтому «поправил в markdown —
пересобрал — перетащил снова» даёт второй журнал с чистым ходом, а прогресс
остаётся в первом, со старыми стрелками. Для этого есть пункт меню
**«Ветви: обновить из компендиума»**: журнал остаётся тот же, схема приезжает
свежая, пройденное на месте. Текст страниц обновляется по желанию, страницы,
исчезнувшие из источника, по умолчанию остаются — вдруг это заметка на полях,
а не удалённый узел.

Держится это на том, что **id страниц при импорте сохраняются**: Foundry чистит
только корневой `_id`, вложенным оставляет свои. Поэтому страницы мира и пакета
сопоставляются по id, и переименование узла связь не рвёт.

**Пройденное при этом не трогается.** Ход кампании — какие узлы отмечены,
какие метки подняты — лежит в отдельном флаге `ход`, и сборка его не пишет
вовсе. Сценарий можно переписать и перенести заново хоть посреди кампании:
стрелки обновятся, прогресс ведущего останется.

Узлом становится страница с флагом `узел`. Прочие страницы — просто текст:
вступление сценария, заметка на полях, приложение. Оговорка на случай беды:
если флага нет ни у одной страницы, схема пришла покалеченной, и узлами
считаются все — лучше лишние узлы, чем пустой холст вместо сценария.

Формат блока `vetvi` описан в `CLAUDE.md` репозитория Девалока, рядом
с остальными полями карточки.

## Вид узла — не украшение

**◆ Сцена** остаётся открытой: к брошенной зацепке можно вернуться через месяц.
**◇ Развилка** захлопывается: как только пройден один её выход, остальные закрыты
навсегда, даже если к развилке ведёт обходная дорога. **★ Финал** — итог, который
считается.

Без правила развилки счёт был бы пустым: до любого узла почти всегда есть
обходная дорога, и «отрезано» не сработало бы никогда.

## Метки и финалы

Метка — короткий факт о мире: «барон жив», «печать сломана». Узел метки ставит и
снимает, стрелка их требует; метку можно переключить и руками — за столом
случается всякое.

Каждый финал помечен: **состоялся**, **ещё возможен** или **отрезан**. Считается
неподвижной точкой: достижимый узел добавляет свои метки, новая метка открывает
стрелки, стрелки добавляют узлы — пока растут.

**Про честность.** Пока метки только накапливаются, счёт точен. Но узел может
метку и снять, и тогда задача становится неточной — модуль считает **сверху**:
объявленное отрезанным отрезано наверняка, а «ещё возможен» значит «при удачном
стечении». Обратное обещание было бы враньём.

## Несколько партий по одному сценарию

Ведущий одного мира может водить в нём две компании. Схема тогда общая, а ход —
свой у каждой партии: узлы, стрелки, метки и ветки пишутся один раз, а
пройденное, поднятые метки и замечания к узлам принадлежат партии.

Партия выбирается первым разделом панели, и её название стоит в заголовке окна:
отметить пройденное не той компании легко, а заметить это потом трудно. На
карточках узлов видны цветные точки партий, которые здесь уже были, — иначе
две партии в одном мире слепы друг к другу.

Кнопка **«Раскол»** заводит партию, перенявшую ход текущей: половина игроков
ушла своим путём с того же места.

Сценарий, который водили до появления этой возможности, отдаёт свой прогресс
первой партии сам, при первом открытии графа.

## Язык

Модуль говорит на языке, выбранном в Foundry: русский в исходнике, английский
словарём `lang/en.json`. Переключение — обычная настройка языка игры, ничего
своего для этого включать не надо.

Устроено как в gettext: ключ словаря — сама русская фраза, а не выдуманный
`UOVETVI.Panel.Button.42`. Так в коде остаётся живой текст, а непереведённое
видно сразу — оно просто остаётся русским, а не превращается в пустоту.

Штатные `languages` манифеста для этого не годятся: Foundry сливает языковые
файлы через `mergeObject`, а тот разворачивает ключи с точками в дерево —
фраза с точкой посреди превратилась бы в цепочку вложенных объектов. Поэтому
словарь читается сам, а язык всё равно берётся у Foundry.

Собрать словарь и свериться:

```bash
npm run yazyk
```

Инструмент вычитывает из кода все `Т("…")` и `М("…")`, добавляет новые фразы
в словарь пустыми, выбрасывает исчезнувшие и ругается на расхождения:
непереведённое, разошедшиеся подстановки, забытую кириллицу. С `--pravit`
записывает, с `--dikari` показывает, что ещё не обёрнуто.

## Проверка

Правила достижимости не знают ни Foundry, ни журналов, поэтому гоняются без
запуска мира:

```bash
node tools/vetvi-proverka.mjs
```

Слой над журналами проверяется там же на заглушках. Модуль говорит ведущему
«этот финал отрезан» — утверждение о кампании, которую ведут месяцами, и
проверять его на живой игре поздно.
